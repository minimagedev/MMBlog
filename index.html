MiniMage Project

MiniMage

A minimal Debian-derived operating system built around efficiency, transparency, OpenRC, Mage, and user control.

PRIVATE PRE-RELEASE DEVELOPMENT

Overview

MiniMage is a lightweight Linux distribution designed to provide the reliability and software compatibility of Debian without carrying the full weight of a conventional general-purpose installation.

The project is built around three primary goals: reduce unnecessary software, simplify system management, and preserve user control.

MiniMage achieves this through a carefully reduced base system, OpenRC service management, the Mage package manager, a custom installation environment, and an image-building process designed around producing small and reproducible systems.

Alongside the primary Linux edition, MiniMage is also being used as an experimental platform for GNU Hurd.

A Smaller Foundation

Conventional Linux distributions often install software for a wide variety of potential use cases. This makes sense for systems intended to work immediately for almost everyone, but it can also leave a machine carrying packages and services it will never use.

MiniMage approaches the problem from the opposite direction.

Instead of asking what the user might need, MiniMage starts with what the operating system actually requires.

A base MiniMage installation does not require a desktop environment, display manager, graphical application suite, development environment, printing stack, or other optional subsystems.

Those components remain available. They simply aren't installed until the user chooses them.

This reduces package count, disk usage, background services, update surface, and overall system complexity.

Smaller Installation Media

MiniMage's reduced package selection allows the project to produce a substantially smaller installation image than a conventional desktop-oriented distribution.

The image focuses on what is required to boot MiniMage, establish networking, install the operating system, manage packages, and recover the machine.

Large graphical environments and application collections are not included simply because a user might eventually install them.

MiniMage does not treat ISO size as a competition. A smaller image is instead a consequence of keeping the base system disciplined.

Every component included by default should have a reason to be there.

Debian Foundation

MiniMage uses Debian as its upstream software foundation.

This provides access to Debian's package ecosystem, the .deb format, dpkg, mature dependency resolution, hardware support, and existing software repositories.

MiniMage does not reproduce a normal Debian installation, however. Its package manifests, OpenRC configuration, installer, service defaults, boot environment, and system configuration are maintained specifically for MiniMage.

Debian provides the foundation. MiniMage determines what gets built on top of it.

Mage Package Manager

Mage is MiniMage's primary package-management interface.

Mage does not introduce an incompatible package format. MiniMage remains based on Debian-compatible .deb packages and uses the existing dpkg/APT infrastructure underneath.

Mage provides a cleaner MiniMage-specific interface above that infrastructure. 

mage install firefox-esr
mage remove firefox-esr
mage search firefox
mage update
mage upgrade

Mage also provides a location for MiniMage-specific functionality including repositories, system profiles, package groups, dependency operations, and distribution packages.

Advanced users are not prevented from using APT or dpkg directly. Mage is an additional system-management layer, not an attempt to hide the underlying package system.

Mage Profiles

Mage profiles allow a minimal MiniMage installation to be expanded into a specific type of machine without requiring those packages to exist in the base image.

minimal Core MiniMage environment.
desktop Foundation for graphical workstations.
development Compilers and development tooling.
server Server-oriented system components.

MiniMage therefore doesn't make useful software unavailable in the name of minimalism. It makes that software optional.

OpenRC

MiniMage uses OpenRC for initialization and service management.

OpenRC fits MiniMage's preference for a relatively small, explicit, and modular operating-system environment. 

rc-service sshd start
rc-update add sshd default
rc-status

MiniMage provides its own runlevel configuration and service defaults. Only services required by the installed configuration are expected to run automatically.

The project does not use OpenRC simply to position itself as anti-systemd. OpenRC is used because its design fits MiniMage.

The MiniMage Installer

MiniMage includes its own installation environment designed around the distribution's minimal base system.

The installer handles:

  • disk preparation and filesystem creation
  • base-system deployment
  • user and hostname configuration
  • network configuration
  • OpenRC setup
  • bootloader installation
  • Mage configuration
  • repository initialization
  • MiniMage system configuration

The installer automates repetitive system construction without making the resulting installation opaque.

After installation, the machine remains a normal Linux system that can be inspected and modified directly.

No Mandatory Desktop

MiniMage deliberately has no mandatory desktop environment.

A workstation may run XFCE or LXQt. A minimal machine may use DWM. A Wayland system can use a compositor selected by the user. A server can contain no graphical stack at all.

The graphical environment sits on top of MiniMage rather than defining MiniMage itself.

Reducing Bloat

MiniMage does not attempt to reduce bloat by rewriting every existing Linux component.

Instead, it reduces complexity at the distribution level.

  • Don't install a graphical stack on a machine that doesn't need one.
  • Don't enable services merely because another installation profile might use them.
  • Don't put development tools in every base installation.
  • Don't duplicate infrastructure Debian already maintains effectively.
  • Don't make optional software part of the core operating system.

The result is a smaller image, fewer default packages, fewer active services, reduced storage requirements, and a system with fewer components to understand and maintain.

Minimal by default. Expandable by design.

GNU Hurd

Linux is MiniMage's primary platform, but MiniMage is also being used to explore an experimental GNU Hurd edition.

GNU Hurd differs substantially from Linux. Instead of a conventional monolithic Linux kernel, Hurd operates using GNU Mach and a collection of userspace servers.

MiniMage Hurd is intended to investigate how much of MiniMage's package-management interface, userspace configuration, installer concepts, package selection, and overall philosophy can remain independent of Linux itself.

MiniMage Linux MiniMage → Debian userspace → Linux
MiniMage Hurd MiniMage → Debian GNU → Hurd → GNU Mach

The Hurd edition is experimental and is not intended to replace the primary Linux edition.

Linux is the platform. Hurd is the laboratory.

Build Process

MiniMage images are generated through an automated build environment using Debian's underlying image infrastructure together with MiniMage-specific tooling.

      ↓

      ↓

Development images are tested from clean virtual disks to ensure that an image can boot, install, configure OpenRC, install its bootloader, reboot independently, establish networking, and perform package operations through Mage.

Development Status

MiniMage is currently in private pre-release development.

Development images and source repositories are not currently available for public download. The build system, installer, Mage package manager, OpenRC configuration, package manifests, filesystem overlays, release tooling, and experimental Hurd work remain private while the project's core architecture is stabilized.

The MiniMage Approach

MiniMage isn't trying to become independent simply for the sake of being independent.

Debian already maintains an enormous software ecosystem. dpkg works. Linux works. OpenRC works.

MiniMage builds around proven components and introduces new software only where it serves the design of the distribution.

The goal is a system that is small enough to understand, complete enough to use, flexible enough to rebuild, and experimental enough to question its own assumptions.

Start small. Add what you need. Understand what you run.
