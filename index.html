Overview

MiniMage is a general-purpose Linux distribution designed to provide a smaller and more transparent starting point than a conventional desktop installation.

The project uses Debian as its upstream software foundation while maintaining its own base package selection, OpenRC configuration, installation environment, system defaults, package-management interface, and release images.

MiniMage does not attempt to replace established components simply for the sake of independence. Instead, it focuses on reducing unnecessary defaults and providing a coherent environment in which optional functionality is installed when it is actually required.

Reduced base system

Optional desktop, development, printing, multimedia, and workstation components are excluded from the core installation.

OpenRC

System initialization and service management are built around OpenRC with MiniMage-specific runlevel defaults.

Debian compatibility

MiniMage retains Debian's .deb ecosystem and underlying dpkg/APT infrastructure.

Modular installation

Graphical environments and specialized software stacks remain optional rather than becoming part of every installation.

Reduced by design

MiniMage treats a small system as an architectural property rather than a benchmark.

Many general-purpose distributions include software intended to satisfy a broad range of potential workloads. MiniMage instead begins with the components required to boot, configure, network, update, install, and recover the operating system.

A base installation does not require a graphical desktop, display manager, office suite, development toolchain, printing environment, or large collection of background services.

This approach reduces the number of packages in the default system, lowers storage requirements, limits unnecessary service activation, and produces smaller installation media.

Small without artificial restrictions. MiniMage's objective is not to remove functionality for the sake of producing the smallest possible ISO. Software that does not belong in the base system remains available through package management.

Mage

Mage is the primary package-management interface provided by MiniMage.

MiniMage retains Debian-compatible packages rather than introducing a new binary package format. Mage operates above the existing package infrastructure and provides a consistent interface for both upstream and MiniMage-specific software management. 

$ mage update
$ mage search firefox
$ mage install firefox-esr
$ mage remove firefox-esr
$ mage upgrade

Mage also provides the integration point for MiniMage repositories, package groups, system profiles, and distribution-specific package operations.

The underlying package tools remain accessible. Experienced users may continue to use APT and dpkg directly when lower-level control is required.

Installation

MiniMage installation media contains a dedicated environment for deploying the distribution onto a new system.

The installation process handles filesystem preparation, base-system deployment, user configuration, networking, OpenRC initialization, bootloader installation, Mage setup, repository configuration, and MiniMage-specific system configuration.

The resulting installation remains a conventional, directly configurable Unix-like environment. The installer automates system deployment without introducing a proprietary configuration layer between the administrator and the operating system.

Installation image

MiniMage installation images are intentionally kept smaller than full desktop-oriented installation media.

The image contains the MiniMage installation environment, kernel, essential boot components, networking support, package-management infrastructure, OpenRC, Mage, and the components necessary to construct an installed system.

Large desktop environments and application collections are not embedded into the base image. They are retrieved only when selected by the administrator.

Exact image sizes vary between development builds as hardware support and package manifests are revised.

MiniMage Hurd

MiniMage Hurd is an experimental port investigating how much of the MiniMage environment can operate independently of the Linux kernel.

The experimental edition uses Debian GNU/Hurd as its foundation, replacing the Linux kernel environment with GNU Mach and the GNU Hurd server architecture.

The Hurd port is not intended to replace MiniMage Linux. It exists as a research target for portability, userspace separation, and experimentation with non-Linux system architecture.

Linux is the primary supported platform. MiniMage Hurd should be considered experimental and is developed independently of the primary Linux release target.

Development status

MiniMage is currently under private pre-release development.

The project is not presently distributed as a public release. Development installation images, source repositories, build configuration, Mage source code, installer code, package manifests, OpenRC configuration, and experimental Hurd work are currently maintained privately.

Public source and installation media are planned after the core system interfaces and release process have stabilized sufficiently for external testing.

No public downloads are currently available. Screenshots, development notes, and technical documentation may describe components from internal builds that have not yet been published.

Project direction

MiniMage is intended to remain conservative about what belongs in the operating system itself.

Debian provides a mature software ecosystem. OpenRC provides service management. Linux provides the primary kernel environment. MiniMage builds a smaller, coherent distribution around those components rather than replacing them without a technical reason.

Components developed specifically for MiniMage are intended to solve distribution-level problems: installation, package workflow, profiles, configuration, image construction, and system integration.

Minimal by default. Expandable by design.
